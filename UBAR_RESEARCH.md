# Исследование uBar и заимствуемые фичи

> Дата: 13.08. Источники: https://ubarapp.com/ (overview) и
> https://ubarapp.com/documentation (документация). uBar 4 — платный
> (Personal $30, Commercial $50), macOS 10.13+, режимы «Dock» и «Task bar».

Цель документа — зафиксировать, что умеет uBar, что из этого у нас уже есть,
и какие фичи стоит позаимствовать (с честной оценкой реализуемости), чтобы не
изобретать велосипед и не пропустить полезное.

---

## 1. Главный архитектурный инсайт: разделение прав по назначению

uBar жёстко разводит два системных разрешения под разные задачи:

| Разрешение | Что делает uBar через него |
|---|---|
| **Accessibility** | действия над окнами: quit приложения, закрыть/развернуть/свернуть окно |
| **Screen Recording** | чтение заголовков окон, отражение открытия новых окон, захват содержимого для превью |

**Это критично для нас.** Сейчас мы читаем и перечисляем окна, и читаем их
заголовки — через Accessibility (`kAXWindowsAttribute` + `kAXTitleAttribute`).
Именно поэтому у нас в `WindowManager.makeWindowInfo` есть фильтр «окна без
заголовка отбрасываем» — AX-заголовок часто пустой/устаревший, особенно у
Electron/web-приложений (мы это уже видели на OpenCode).

uBar вместо этого использует Screen Recording (фактически
`CGWindowListCopyWindowInfo`), который даёт `kCGWindowName` надёжнее и, кроме
заголовка, сразу отдаёт: номер окна `kCGWindowNumber` (стабильный id в рамках
сессии), `kCGWindowOwnerName`, `kCGWindowOwnerPID`, `kCGWindowBounds` (в
Quartz-координатах), `kCGWindowIsOnscreen`, `kCGWindowAlpha`,
`kCGWindowMemoryUsage`.

**Рекомендация (приоритетная):** перейти на CGWindowList для перечисления и
метаданных окон, оставив AX только для действий (raise/minimize/close/move).
Это развязывает нам руки для превью и надёжных заголовков и убирает хрупкий
фильтр по пустому заголовку. Минус — нужно дополнительное разрешение Screen
Recording (плюс к уже запрашиваемому Accessibility).

## 2. Полный инвентарь фич uBar и статус у нас

Легенда: ✅ уже есть · 🟡 частично/иное · ❌ нет.

### Работа с окнами
- ✅ Группировка окон по приложению (у нас — Always; у uBar Always/Never/Automatic).
- ✅ Список окон приложения по клику/меню (у нас — в контекстном меню ПКМ).
- ✅ Бейдж количества окон (у нас — красный бейдж; у uBar `showWindowCount`).
- ❌ **Превью окон по hover** (живые миниатюры) — требует Screen Recording.
- 🟡 Per-monitor окна: у нас панель на каждом экране, но список окон один и тот же;
  у uBar «каждый экран показывает только свои окна» либо Mirror-режим. **Нам не хватает
  именно «свои окна на экране»**.
- ❌ «Клик по активному приложению скрывает его» (taskbar-поведение, дефолт у uBar в taskbar-режиме).
- ❌ Клавиатурные модификаторы клика: Option-клик скрыть/показать, Shift-клик quit,
  Cmd-клик показать в Finder, Option-Cmd-клик «показать только его (скрыть остальные)»,
  Shift-Cmd-клик force relaunch, middle-click закрыть.

### Статусы приложений (визуальные сигналы на плитке)
- ❌ **App Flashes** — мигание плитки при запросе внимания (аналог bounce Dock). Внимание
  бывает «информационное» (мигнуть ~1с) и «критическое» (мигать, пока не переключишься).
- ❌ **App Status** — диагональные штрихи: launching (белый), restorable (синий),
  unresponsive (красный).
- ❌ **App Progress** — позиция трека в медиа-плеерах (Music/Spotify/VLC).
- ❌ **App Activity** — удержание модификатора (по умолч. правый Control) показывает
  %CPU и RAM каждой плитки.
- 🟡 **App Badges** — настоящие бейджи приложений (непрочитанные письма Mail и т.п.).
  У нас только счётчик окон; кросс-приложенческих бейджей нет (см. п.3.5).

### Позиционирование/внешний вид
- ✅ Нижняя панель на всех экранах (у uBar ещё «каждая сторона экрана»: top/left/right).
- ❌ Pinning (прижать к углу / свободно плавать), раскрытие до 5 рядов перетаскиванием.
- ❌ Темы (System/Light/Dark/Platinum/Custom), размеры (Automatic/Small/…/Huge).
- ❌ Clock Area (день/дата/время) + hover-календарь, по клику — запуск календаря.

### Приложения/навигация
- 🟡 Порядок приложений: у нас alphabetical; у uBar Launch/Alphabetical/Manual.
- ❌ Favorites Area (закреплённые приложения, папки, файлы).
- ❌ Drag-and-Drop файлов/папок на плитку для открытия в приложении.
- ❌ Горячие клавиши Ctrl-Opt-1…0 — переключить приложение/окно по позиции.
- ❌ uBar Menu (список приложений, системных настроек, кастомные папки).
- ❌ «0 окон = плитка приложения (toggle видимости); 1+ окон = стек окон» — у нас
  приложение без окон вообще скрыто (это разумно для нашей задачи, можно не менять).

## 3. Что заимствовать: приоритеты и честная оценка сложности

### Tier 1 — высокая ценность, реализуемо сейчас

**3.1 Per-monitor окна** (экран показывает только окна, физически находящиеся на нём).
- Сложность: низкая. У нас уже есть `WindowInfo.frame`; достаточно при рендере каждой
  панели фильтровать `app.windows` по принадлежности к `screen` (через
  `ScreenCoordinateConverter.screenContaining`). Отдельный вопрос UX: что делать с
  приложением, у которого окна на обоих экранах — показывать на обоих.

**3.2 «Клик по активному приложению скрывает его»** (taskbar-поведение).
- Сложность: низкая. При клике, если `app.isActive`, сворачиваем все окна
  (`AXUIElementSetAttributeValue(kAXMinimizedAttribute, true)`). Идемпотентно.

**3.3 Клавиатурные модификаторы клика** (Option-клик скрыть, Shift-клик quit,
Cmd-клик показать в Finder, middle-click закрыть).
- Сложность: низкая–средняя. В `NSClickGestureRecognizer` читать `NSEvent.modifierFlags`
  (`event.modifierFlags` из `mouseDown`/`rightMouseDown`), либо переопределить
  `mouseDown(with:)`. `NSRunningApplication.terminate()` для quit,
  `NSWorkspace.shared.activateFileViewerSelecting` для Finder.

**3.4 Заголовки/перечисление окон через CGWindowList** (см. п.1).
- Сложность: средняя (затрагивает ядро `WindowManager` + добавляет разрешение Screen
  Recording). Даёт стабильный `kCGWindowNumber` как id вместо `CFHash(AXElement)`,
  надёжные заголовки, `kCGWindowIsOnscreen`, `kCGWindowMemoryUsage` — фундамент для
  превью и Activity Mode.

### Tier 2 — высокая ценность, средняя сложность

**3.5 App Badges (реальные бейджи).**
- Сложность: высокая/блокер. Публичного API для чтения бейджа чужого приложения нет —
  Dock получает его из `NSApplication.dockTile.badgeLabel`, который ставит само
  приложение. Чтение требует private API (например `_DPLHiliteMenuGlyph`/Dock-related
  SPI). **Рекомендация: отложить**, возможно нереализуемо без private API.

**3.6 Превью окон по hover.**
- Сложность: средняя. Захват миниатюры окна через Screen CaptureKit / `CGWindowListCreateImage`
  (нужно Screen Recording). Показ — отдельный floating `NSPanel` с `NSImageView` по
  hover-таймеру. Уже частично заложено в план как Фаза 4.

**3.7 App Activity (CPU/RAM по удержанию модификатора).**
- Сложность: средняя. `proc_pidinfo` / `task_info` дают CPU и RSS. Показ — подмена
  заголовка/наложение на плитку при удержании клавиши (NSEvent local key monitoring).

**3.8 Clock Area + hover-календарь.**
- Сложность: низкая–средняя. `Date` + `NSTextField` в правом конце панели; hover —
  `NSCalendar` в маленьком `NSPopover`/`NSPanel`. Чисто косметика, но быстро.

### Tier 3 — косметика/низкий приоритет

**3.9** Темы, размеры, позиции (top/left/right), pinning, раскрытие до 5 рядов,
Favorites Area, drag-and-drop, горячие клавиши Ctrl-Opt-1…0, uBar Menu.
- Сложность: разная, но ценность для личной задачи ниже. Драг-н-дроп и Favorites —
  полезны, но не критичны на этом этапе.

### Сознательно НЕ заимствуем (или отдельно решаем)

- **App Flashes (attention)**: очень полезно (замена bounce), но публичного способа
  «подслушать» `requestUserAttention` другого приложения нет; uBar, судя по всему,
  использует приватный Dock SPI. Пометить как «исследовать private API позже».
- **App Status (launching/restorable/unresponsive)**: launching/restorable ловятся через
  LaunchServices-нотификации; **unresponsive** нетривиален (нужен probe: замерить отклик
  приложения на событие — с пиццей «не отвечает» связан `kCGWindowIsOnscreen`/AppleEvent
  timeout). Отложить.
- **App Progress (медиа-трек)**: сложно и малополезно вне конкретных плееров — отложить.

## 4. Пересмотр нашего roadmap с учётом uBar

Рекомендую дополнить `ARCHITECTURE.md` п.11 следующими пунктами (по приоритету):

1. Per-monitor окна (Tier 1) — в текущую итерацию.
2. «Клик по активному приложению скрывает» + модификаторы клика (Tier 1).
3. Переход ядра на CGWindowList (Tier 1, фундамент для превью/activity) — перед Фазой 4.
4. Clock Area (Tier 2, дешёвая).
5. Превью по hover + Activity Mode (Tier 2) — Фаза 4.
6. App Flashes/Status/Badges — только после исследования private API (рискованно).

Ключевой вывод: uBar подтверждает, что **наш вектор верный** (та же связка
Accessibility + окна, тот же taskbar-режим, та же идея «список окон по клику»),
а главные отличия uBar, которые мы можем быстро забрать — это per-monitor окна,
модификаторы клика и CGWindowList вместо AX-заголовков.
